## Changes

ContextTrace v0.1.15 fixes repeated instruction-change notifications and makes cache and context usage clearer.

- Stop treating growing Claude prompt snapshots, ordinary files and unrelated instruction attachments as changed instructions. Historical instruction findings no longer replay when a log grows or monitoring resumes.
- Preserve Codex cached input separately from fresh input, applying the cache-read price without double-counting context tokens.
- Show recorded fresh-input, cache-read and cache-write token counts, cache-read share and coverage independently of price availability. Unreported cache buckets stay unknown; token shares are not cache lookup hit/miss counts.
- Show context tokens used and the total recorded window alongside the percentage and selected model. A model switch does not inherit another model's window when its own limit is missing.
- Leave incomplete cache splits and combined multi-call records explicitly unpriced instead of presenting misleading complete spend or forecasts.

## Requirements and verification limits

Pricing remains an estimate of standard text-token API list prices, not a subscription invoice. Nondefault cache durations, negotiated rates and tool/media charges are outside its scope. Claude multi-call context samples retain the largest request's input, not the billable total across all calls. Unknown context limits and cache fields are not inferred. See [cache and context usage](https://github.com/aneskurtovic/ContextTrace/blob/main/docs/cache-and-context-usage.md).

Local development checks passed: 508 Rust tests (one ignored), formatting and strict Clippy, 180 frontend tests, the frontend production build, all 17 fixture entries, fixture-validator regressions and PowerShell 5.1 release-note checks.

Woodpecker validates the exact main commit before tag packaging, publication and uploaded-asset verification. See [MVP status](https://github.com/aneskurtovic/ContextTrace/blob/main/docs/MVP-STATUS.md) for pipeline results. Separate clean-host installer/updater acceptance and native desktop visual QA remain unverified. Parser compatibility remains scoped to the compatibility catalog.
